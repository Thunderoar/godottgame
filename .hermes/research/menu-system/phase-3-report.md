## 4. Deviations

1. **`tutorial_guide.gd` gained a vertical clamp.** The `ui_scale` requirement says every HUD panel
   must stay inside the scaled root. At 832x480 + 130 % the root is 640x369 of layout space while
   the tutorial card sat at y 184..442 and overflowed (caught by the probe, the only offender).
   `_fit_vertical()` clamps its top to `host.size.y - 22 - 258` and re-runs on the root's `resized`.
   At 1280x720 and 832x480 @100 % the rect is byte-identical to before (184..442).
2. **`TitleScreen.refresh_save_state()` is new.** The erase row must refresh Continue; the
   alternative was writing `title_screen._continue_button.disabled` from the panel, i.e. reaching
   into another class's private.
3. **`ModalBase` refits on every open**, not only at construction. Panels are constructed at HUD
   boot, before `apply_ui_scale()` runs, so a panel built at 100 % and opened at 130 % would
   otherwise be sized against a root that no longer exists. Verified with a `ModalBase` built at
   75 % and opened at 130 %.
4. **`SettingsPanel.close_panel()` does not clear the body.** The brief requires building rows once;
   `ModalBase.close_panel()` frees the content, which would force a rebuild on every open. Inline
   `_dirty` tracking flushes a keyboard-only slider change on close (`save_settings()`), because
   arrow-key edits never fire `drag_ended`.
5. **The Pause help row reads "Not bound" today.** `pause_menu` is added to `InputMap` in phase 4.
   The row is built from `InputMap` live, so it becomes "P" automatically; no binding was invented.
6. **Title/pause instances are not affected by `ui_scale`.** D3 parents them outside the HUD root
   (title layer / pause layer), so they stay 1:1 and remain readable when the HUD is enlarged. The
   fit change covers panels parented to the HUD root, which is the case the spec names.
7. **`_panel_size = Vector2(880, 620)`** for the settings panel (fits 1280x720; clamped to
   800x448 at 832x480 by the base class).
8. **Temporary tooling:** `tools/p3_probe.gd` (a `--script` SceneTree probe — `--script` main loops
   are compiled before autoload names register, so it reaches autoloads via `root.get_node`). It was
   deleted after the run, together with its `.uid`; the shipped tree adds no `.tscn` and no tooling.
   A copy is outside the tree at `~/.hermes/cache/scratch/p3_probe.gd.keep` if the run must be
   reproduced (re-add it as `tools/p3_probe.gd` and run
   `XDG_DATA_HOME=$HOME/.hermes/cache/scratch/godotuser godot --headless --path . --script res://tools/p3_probe.gd`).
9. **Pre-existing warning:** the suite prints `WARNING: 4 ObjectDB instances were leaked at exit`.
   The same line is in the phase-1/2 baseline logs (`p12_suite.log`, `p12_suite_p1.log`), so it is
   not from this change; the final run did not print it at all (timing-dependent, nodes alive at
   `quit()`).
